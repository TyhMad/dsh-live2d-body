# 和现有的同类项目比（2026-11）

检索时能直接找到的、和「AI + Live2D 身体」沾边的公开项目有四类。下面只比**能力**，不比热度。

| 项目 | 形态 | 身体能力 | 状态回执 | 自拍/看图 | 多端 | 语音 |
|---|---|---|---|---|---|---|
| **dsh-live2d-pets**（[cyanfish-x](https://github.com/cyanfish-x/dsh-live2d-pets)） | DSH 插件，npm 包，内置宽松许可预设模型 | 状态镜像 + 少量互动，动作表驱动 | 无 | 无 | 单机 | 无 |
| **dsh-fish-river**（[bychance6600](https://github.com/bychance6600/dsh-fish-river)） | DSH 插件（某个角色皮的整合版） | **没有身体**，是人格/记忆/渠道整合 | — | — | QQ / B站私信 / 抖音 | 无 |
| **AAAAGENT**（[phoiex](https://github.com/phoiex/AAAAGENT)） | 独立应用，macOS-first | Live2D 伴侣，动作/表情偏「播片」 | 无 | 无 | 微信 / QQ | **有**（TTS + ASR） |
| **DesktopFriends**（[tosuke-sama](https://tosuke-sama.github.io/DesktopFriends/guide/)） | 桌面应用 | 桌宠（待机动作 + 交互） | 无 | 无 | 单机 | 无 |
| **dsh-live2d-body**（本项目） | DSH 插件 + 渲染服务 | 509 参数 / 25 通道词表 / 7 层混合 / 物理波形 | **有**（做人话回执） | **有**（canvas 自拍 → 视觉模型） | 桌面 + 网页 + 手机（同一份现场） | 规划中 |

## 逐项差距

**我们更强的：**

1. **参数级而不是动作级**：别人的「歪头」是播一段 motion3，我们的「歪头」是往 4 个参数上写值，可以和她要的「有点」「很」一起缩放，可以和「眯眼」叠加成词表里没有的组合。
2. **分层混合 + 优先级**：情绪当底色、表情覆盖 25 秒、姿态/手动优先；同优先级「后下的命令接管」。别人的表情基本是「播完回弹」。
3. **身体状态是回执的一部分**：每次动作返回「做了什么 + 现在什么脸」，她能自己回答「我现在什么表情」，也支持 `status` 主动查。
4. **自拍**：`app.renderer.extract.canvas()` 抽当前帧 → dataUrl → 视觉模型。这是「她看见自己的脸」的最小闭环，同类项目里没见到。
5. **现场持久化**：`scene.json` 存姿态/表情/道具/大小/情绪/词表，换设备、刷新、重启服务都还原；别人的桌宠重启即归零。
6. **跨端同一具身体**：电脑透明窗口 + 手机浏览器共用云端那台服务，下命令是广播，谁开着谁就在动。

**别人更强的：**

1. **语音**（AAAAGENT）：TTS + ASR 已经打通；我们这条线停在「音色不满意」，代码没接进 QQ。
2. **人格/记忆**（fish-river）：三层记忆、成长、主动拒绝，是独立一整套；我们只有 `heart`（七根情绪的衰减账本）+ 宿主原有记忆。
3. **分发**（dsh-live2d-pets）：npm 包 + 开箱可用 + 自带授权模型；我们是源码级，还得自备模型。
4. **平台覆盖**（AAAAGENT）：微信也在内；我们目前 QQ + 网页。

## 结论

- 如果要「装上去就能用的桌宠」→ 用 **dsh-live2d-pets**。
- 如果要「人格长出来的鱼」→ 用 **dsh-fish-river**。
- 如果要「语音伴侣」→ 看 **AAAAGENT**（注意它的非商业许可）。
- 如果要「能被程序精确使唤、还能自己看自己」的身体层 → 目前公开项目里没有同等实现，本项目补的是这一层。
